# «Муравьи-фуражиры 3D» — порт на VK Mini Apps

Один и тот же `index.html` теперь работает на двух площадках. Какая именно — решается
в первом же скрипте страницы, по query-параметрам запуска:

| | YouTube Playables | VK | Одноклассники |
|---|---|---|---|
| Определяется по | нет `vk_*` в URL | `vk_app_id` / `vk_platform` / webview | `vk_client=ok` (+ API-хост OK) |
| SDK | `ytgame` (грузится через `document.write`) | `vkBridge` (встроен в страницу) | `vkBridge` |
| Сохранения | `ytgame.game.saveData` | VK Storage + зеркало в `localStorage` | то же |
| Реклама | `ytgame.ads` | `VKWebAppShowNativeAds` | то же |
| Покупки | запрещены платформой | `VKWebAppShowOrderBox` | **витрина не создаётся** |
| Web Storage | не трогается вообще | используется как зеркало | то же |

Ветки не пересекаются: на VK объект `ytgame` не появляется даже теоретически —
скрипт YouTube не загружается, а `hasYTSDK` дополнительно требует `!VKP.active`.
Это важнее, чем кажется: старая проверка считала «мы внутри iframe» достаточным
признаком Playables, а VK Mini App — это как раз iframe.

## Что нужно сделать до запуска

### 1. Зарегистрировать товары в панели приложения

`item_id` в панели должны совпасть со строками в `vkProducts` (внизу `index.html`):

| `item_id` | Что даёт | Цена (голоса) |
|---|---|---|
| `ants_lives_refill` | полный запас жизней | 1 |
| `ants_lives_unlimited_24h` | сутки без счётчика жизней | 5 |
| `ants_no_ads` | никакой рекламы между уровнями, навсегда | 20 |

Цена живёт в **трёх** местах и должна совпадать во всех: `price` в `vkProducts`
(только текст на кнопке), `CATALOGUE` в `server/vk-payments.js` (именно отсюда VK
берёт реальную сумму) и то, что видит игрок в диалоге оплаты. Расхождение игрок
увидит ровно в момент решения заплатить.

### 2. Указать адрес обработчика уведомлений ⚠️

**Это единственный пункт задания, который я не смог выполнить: в тексте на месте
адреса стояло «[link removed]».** Всё остальное готово и ждёт URL. Когда он будет:

1. В панели приложения → «Платежи» → указать `https://<ваш-хост>/vk/callback`.
2. В `index.html` найти `orderVerifyUrl: ''` (в блоке `CONF` слоя VK) и вписать
   `https://<ваш-хост>/vk/verify`.

Пока `orderVerifyUrl` пуст, покупка засчитывается **по слову клиента** — этого
достаточно для тестов и категорически недостаточно для продакшена. Самопроверка
на старте предупреждает об этом в консоли.

### 3. Поднять сервер

```bash
VK_APP_ID=<ID> VK_APP_SECRET=<Защищённый ключ> VK_SECURE_KEY=<Сервисный ключ> node server/vk-payments.js
```

Без зависимостей, обычный `node:http`. Два эндпоинта:

* `POST /vk/callback` — сюда стучится VK. Подпись `sig` (MD5, **Защищённый ключ**).
  Обрабатывает `get_item` и `order_status_change`; повторные уведомления
  идемпотентны, товар не выдаётся дважды.
* `POST /vk/verify` — сюда стучится игра после `status:'success'`. Подпись `sign`
  из параметров запуска (HMAC-SHA256, **Сервисный ключ**).

Два разных ключа для двух разных схем подписи — перепутать их легко, а отказ
получается молчаливый: подпись просто не сходится, игрок платит, товар не выдаётся.

Хранилище — JSON-файл (`server/orders.json`). Для первого деплоя нормально, дальше
заменить объект `store` на вашу БД: ему нужны четыре метода и никаких транзакций.
Перед публикацией выставить `VK_ALLOW_TEST=0`, иначе тестовые уведомления
продолжат выдавать реальные права.

## Реклама

**Кнопка «СЛЕДУЮЩИЙ УРОВЕНЬ»** бросает монетку на каждое нажатие (как в задании):

* орёл — межстраничная через `VKWebAppShowNativeAds` (`interstitial`);
* решка — баннер `banner.webp` со ссылкой на товар в VK Маркете.

Если межстраничная не показалась (кулдаун 3 минуты или нет заполнения) — вместо
неё показывается баннер, чтобы пауза не оказалась пустой. Доля настраивается:
`interstitialChance` в `CONF`. Крестик на баннере появляется через 2 секунды
(`bannerCloseAfterMs`).

Перед каждым показом вызывается `VKWebAppCheckNativeAds`, как и требовалось.
Отдельно кешируется доступность формата — шелл решает, показывать ли кнопку
рекламы, синхронно, а VK отвечает только асинхронно.

Награда за rewarded-рекламу выдаётся **только** при `result === true`. Закрытая на
половине или незаполненная реклама не оплачивается.

Купленный `ants_no_ads` убирает и межстраничную, и баннер.

## Сохранения

VK Storage — это «ключ → строка» с потолком **4096 байт на ключ**, а не один блоб.
Поэтому сохранение режется на куски по 3800 байт (запас на UTF-8) и пишется как
`ants3d_save_0…N` плюс `ants3d_save_n` со счётчиком. Счётчик пишется **последним**:
прерванная запись оставляет читаемым предыдущее сохранение, а не половину нового.

Параллельно всё пишется в `localStorage` — как и просили. Это не дубль ради дубля:
при неудачном чтении облака запись в облако блокируется на всю сессию (иначе
сетевой сбой затрёт реальный прогресс дефолтами), а зеркало продолжает работать,
и игрок не теряет текущую сессию. На старте берётся более свежее из двух по
метке времени.

На YouTube зеркало не используется вообще — там Web Storage запрещён, и весь код
зеркала закрыт флагом платформы.

## Интерфейс

* **Safe areas** — подписка на `VKWebAppUpdateConfig` и `VKWebAppUpdateInsets`
  (iOS отдаёт отступы в первом, Android во втором). Карточка 450×800 вписывается в
  вьюпорт **минус** отступы, нижняя навигация поднимается над home indicator.
  Значения дублируются в CSS-переменные `--vk-inset-*`, по умолчанию —
  `env(safe-area-inset-*)`, чтобы мобильный браузер тоже не лез под чёлку.
* **Полный экран на мобильных** — `VKWebAppSetViewSettings` на старте. Параметра
  `fullscreen` нет в типах vk-bridge 3.0.2; он отправляется, как и просили, но
  вызов повторяется без него, если клиент отклонит запрос из-за неизвестного поля.
* **Полный экран на десктопе** — кнопка справа на главном экране (HTML5 Fullscreen
  API работает только из настоящего клика, поэтому именно кнопка, а не вызов на
  старте).
* **Пауза/возобновление** — `VKWebAppViewHide` / `VKWebAppViewRestore` плюс
  `visibilitychange` для мобильного браузера, где события моста не приходят.

## Локальная отладка

```bash
python -m http.server 8765
```

Затем:

* `http://localhost:8765/index.html` — ветка YouTube, как раньше;
* `http://localhost:8765/index.html?vk=1&debug` — ветка VK на машине без клиента VK;
* `…&vk_client=ok` — ветка Одноклассников (проверить, что вкладки «Магазин» нет).

`?vk=1` — только для отладки. Без клиента VK мост не отвечает, поэтому все вызовы
упираются в таймауты: реклама честно становится недоступной, облако — недоступным
для записи, зеркало продолжает работать. Это и есть корректное поведение в
деградации, и его удобно смотреть именно так.

Один артефакт при переключении веток на одном `localhost`: после сессии с `?vk=1`
в `localStorage` остаётся ключ `ants3d_save`, и следующая загрузка **без** `?vk=1`
честно ругается «Web Storage is in use and is FORBIDDEN in Playables». Проверка
права: это её работа. На реальном Playables ветка VK не выполняется и ничего не
пишет; чтобы убрать шум локально — `localStorage.clear()`.

`?debug` включает лог слоя VK и самопроверку в консоли (`Shell.vkPreflight()` можно
позвать и руками). Она проверяет, что мост загрузился, что запуск подписан, что
сохранение реально проходит туда-обратно, что у товаров валидные `item_id` — и
громче всего ругается, если витрина за реальные деньги вдруг оказалась включена в
Одноклассниках.

## Что осталось на вашей стороне

1. **Адрес обработчика уведомлений** — см. пункт 2 выше.
2. **`item_id` в панели** — без регистрации диалог оплаты падает с ошибкой, которую
   игрок прочитает как «игра сломалась».
3. **Цены** — сверить `vkProducts`, `CATALOGUE` и панель.
4. **Иконки и картинки** пока лежат отдельными файлами (`icons/`, `images/`). Для VK
   это допустимо, для сборки Playables — нет: там всё должно быть внутри одного
   файла. Проверка `Shell.preflight()` на ветке YouTube об этом и сообщает; это
   поведение было до порта и не менялось.
